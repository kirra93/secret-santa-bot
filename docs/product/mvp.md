# ТЗ MVP: Telegram-бот «Тайный Санта»

## 1. Цель проекта

Telegram-бот для организации игры «Тайный Санта».

Бот должен позволять пользователю:

1. создать игру;
2. пригласить участников;
3. собрать пожелания участников;
4. провести жеребьёвку;
5. приватно сообщить каждому участнику, кому он дарит подарок;
6. позволить организатору управлять игрой.

Основной интерфейс взаимодействия — Telegram private chat с ботом.

---

# 2. Технологический стек

- TypeScript
- Node.js
- GramIO
- Drizzle ORM
- PostgreSQL для локальной разработки и production
- Docker
- long polling для local development
- long polling для production MVP

Архитектура должна оставаться простой.

Не требуется микросервисная архитектура, CQRS, Event Sourcing или полноценный DDD.

Текущая структура и границы модулей описаны в [обзоре архитектуры](../architecture/overview.md).

---

# 3. Пользователь

После первого `/start` бот регистрирует пользователя.

Минимальные данные:

```text
User
- id
- telegramId
- username
- firstName
- lastName
- createdAt
```

Telegram ID является уникальным идентификатором пользователя Telegram.

---

# 4. Главное меню

После `/start` пользователь получает меню:

```text
🎅 Тайный Санта

[Создать игру]
[Мои игры]
[Помощь]
```

Если пользователь открывает invite-ссылку:

```text
/start game_<inviteCode>
```

бот сразу предлагает ему присоединиться к соответствующей игре.

---

# 5. Создание игры

Пользователь нажимает:

```text
Создать игру
```

Бот пошагово спрашивает параметры.

## Шаг 1. Название

Пример:

```text
Как назовём игру?

Например:
🎄 Новый год 2027
```

Организатор вводит название.

---

## Шаг 2. Бюджет

Бот спрашивает:

```text
Какой бюджет подарка?
```

Варианты:

```text
[До 1000 ₽]
[1000–2000 ₽]
[2000–5000 ₽]
[Указать свой]
[Без ограничения]
```

Для MVP бюджет может храниться просто текстом.

---

## Шаг 3. Дата обмена подарками

Опциональное поле.

```text
Когда будете обмениваться подарками?
```

Можно:

```text
[Указать дату]
[Пропустить]
```

---

## Шаг 4. Создание игры

После заполнения параметров создаётся Game.

Организатор получает:

```text
🎄 Новый год 2027

Участников: 1
Бюджет: до 2000 ₽
Жеребьёвка: ещё не проведена

Приглашай друзей:
https://t.me/<bot>?start=game_<inviteCode>
```

Кнопки:

```text
[Пригласить участников]
[Участники]
[Настройки]
[Провести жеребьёвку]
```

---

# 6. Приглашение участников

Для каждой игры создаётся уникальный `inviteCode`.

Пример deep link:

```text
https://t.me/my_secret_santa_bot?start=game_ab12cd
```

При переходе по ссылке бот показывает:

```text
🎅 Тебя пригласили в Тайного Санту!

Игра:
🎄 Новый год 2027

Организатор:
Кирилл

Бюджет:
до 2000 ₽

[Присоединиться]
[Отказаться]
```

---

# 7. Вступление в игру

После `Присоединиться` создаётся Participant.

```text
Participant
- id
- gameId
- userId
- wishlist
- joinedAt
```

После вступления:

```text
Ты участвуешь в игре 🎄 Новый год 2027.

Теперь можешь добавить пожелания к подарку.
```

Кнопки:

```text
[Добавить пожелания]
[Пропустить]
```

---

# 8. Wishlist

Участник может написать свободный текст.

Например:

```text
Люблю кофе, книги и всякую штуку для рабочего стола.
Не надо алкоголь :)
```

Wishlist можно изменить до проведения жеребьёвки.

Минимальная версия:

```text
wishlist: TEXT | null
```

В дальнейшем можно добавить:

- несколько пожеланий;
- ссылки;
- антипожелания;
- размеры одежды;
- любимые магазины.

Для MVP это не нужно.

---

# 9. Управление участниками

Организатор видит:

```text
Участники: 5

✅ Кирилл
✅ Вика
✅ Андрей
✅ Маша
✅ Сергей
```

Организатор может удалить участника до жеребьёвки.

```text
[Удалить участника]
```

После проведения жеребьёвки состав участников изменять нельзя.

---

# 10. Проведение жеребьёвки

Жеребьёвку может запустить только организатор.

Минимальное количество участников:

```text
3
```

Перед запуском бот показывает подтверждение:

```text
Провести жеребьёвку?

После этого состав участников изменить будет нельзя.

Участников: 6
```

Кнопки:

```text
[🎲 Провести]
[Отмена]
```

---

# 11. Правила жеребьёвки

Каждый участник должен получить ровно одного человека.

Каждому участнику должен дарить подарок ровно один человек.

Нельзя назначить самого себя.

То есть формируется перестановка:

```text
giver -> receiver
```

с условием:

```text
giver != receiver
```

Для MVP достаточно:

1. перемешать список участников;
2. назначить каждому следующего человека;
3. последний участник дарит первому.

Пример:

```text
А → Б
Б → В
В → Г
Г → А
```

Так гарантируются:

- отсутствие self-match;
- один получатель для каждого;
- один даритель для каждого.

---

# 12. Результаты жеребьёвки

Результаты должны быть приватными.

После жеребьёвки каждый участник получает сообщение:

```text
🎅 Жеребьёвка завершена!

Ты Тайный Санта для:

🎁 Виктория

Пожелания:
Люблю кофе, книги и настольные игры.

Бюджет:
до 2000 ₽

Дата обмена:
25 декабря
```

Важно:

участник не должен видеть:

- кто дарит подарок ему;
- результаты остальных участников.

---

# 13. Хранение результатов

```text
Assignment
- id
- gameId
- giverParticipantId
- receiverParticipantId
- createdAt
```

Для пары:

```text
giverParticipantId
receiverParticipantId
```

должны существовать уникальные ограничения в рамках игры.

---

# 14. Мои игры

Пользователь может открыть:

```text
Мои игры
```

Бот разделяет их на:

```text
Организую

🎄 Новый год 2027
👥 6 участников
🎲 жеребьёвка проведена


Участвую

🎁 Santa Dev Team
👥 8 участников
```

При выборе игры открывается её карточка.

# 15. Карточка игры для организатора

```text
🎄 Новый год 2027

👥 Участников: 6
💰 Бюджет: до 2000 ₽
📅 Обмен: 25 декабря
🎲 Жеребьёвка проведена
```

Кнопки:

```text
[Участники]
[Пригласить]
[Настройки]
```

До жеребьёвки также:

```text
[Провести жеребьёвку]
```

---

# 16. Карточка игры для участника

До жеребьёвки:

```text
🎄 Новый год 2027

Ожидаем жеребьёвку.

[Мои пожелания]
[Покинуть игру]
```

После жеребьёвки:

```text
🎄 Новый год 2027

[Кому я дарю 🎁]
[Мои пожелания]
```

---

# 17. Выход из игры

Участник может выйти из игры только до жеребьёвки.

После жеребьёвки выход запрещён.

Для MVP отмена уже проведённой жеребьёвки не реализуется.

---

# 18. Удаление игры

Организатор может удалить игру.

Необходимо подтверждение:

```text
Удалить игру?

Все участники и результаты жеребьёвки будут удалены.
```

```text
[Удалить]
[Отмена]
```

Можно использовать soft delete либо обычное каскадное удаление.

Для MVP допустимо обычное удаление.

---

# 19. Состояния игры

Использовать явный статус:

```ts
enum GameStatus {
  Recruiting = "recruiting",
  Drawn = "drawn",
  Finished = "finished",
}
```

Для первого MVP фактически достаточно:

```text
recruiting
drawn
```

# 21. Основные ограничения

Нельзя:

- вступить в игру дважды;
- провести жеребьёвку при количестве участников < 3;
- провести жеребьёвку повторно;
- изменить участников после жеребьёвки;
- удалить участника после жеребьёвки;
- покинуть игру после жеребьёвки;
- увидеть assignment другого пользователя;
- назначить участника самому себе.

---

# 22. Обработка ошибок

Пользовательские ошибки должны выдавать понятные сообщения.

Например:

```text
Эта игра уже началась, поэтому присоединиться к ней больше нельзя.
```

или:

```text
Ты уже участвуешь в этой игре.
```

Технические ошибки логируются.

Пользователю:

```text
Что-то пошло не так. Попробуй ещё раз.
```

---

# 23. MVP

Первая версия должна включать только:

1. `/start`;
2. регистрацию пользователя;
3. создание игры;
4. invite link;
5. вступление по invite link;
6. список участников;
7. wishlist;
8. жеребьёвку;
9. приватную рассылку результатов;
10. просмотр своих игр;
11. просмотр того, кому пользователь дарит подарок;
12. удаление игры.

Это полноценный рабочий MVP.

---

# 24. Не включать в первый MVP

Не реализовывать сейчас:

- Mini App;
- web frontend;
- группы Telegram;
- OAuth;
- админ-панель;
- Redis;
- очереди;
- Kafka/RabbitMQ;
- сложные роли;
- сложную Clean Architecture;
- платежи;
- AI;
- подбор подарков;
- несколько языков;
- анонимный чат;
- cron-напоминания.

Их можно добавить позже.

# 25. Возможные расширения

После MVP проект можно развивать.

### Исключения при жеребьёвке

Организатор сможет задать:

```text
Кирилл не может получить Вику
Вика не может получить Кирилла
```

Полезно для:

- супругов;
- прошлогодних пар;
- конфликтующих комбинаций.

В этом случае простой circular shuffle заменяется constrained matching.

### Анонимный чат

Санта может отправлять получателю сообщение через бота:

```text
Твой Тайный Санта спрашивает:

Какой кофе ты любишь?
```

Личность Санты не раскрывается.

### Напоминания

```text
До обмена подарками осталось 7 дней 🎁
```

### История игр

```text
Новый год 2026
Новый год 2027
```

Можно учитывать предыдущие пары и не повторять их.

### Дополнительный wishlist

Можно добавить:

- ссылки;
- картинки;
- категории;
- «точно не хочу»;
- любимые магазины.

### Статус подарка

Санта сможет отметить:

```text
🎁 подарок выбран
📦 подарок куплен
✅ готов
```

Получатель статус не видит.

# 26. Критерий готовности MVP

MVP считается готовым, когда можно пройти полный сценарий:

```text
Пользователь A
    ↓
создаёт игру
    ↓
отправляет invite link
    ↓
B и C вступают
    ↓
все добавляют wishlist
    ↓
A запускает draw
    ↓
каждый получает своего Secret Santa recipient
    ↓
никто не получает самого себя
    ↓
результаты остальных недоступны
```

Этот сценарий должен быть покрыт интеграционным тестом.
