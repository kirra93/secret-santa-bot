# Рабочий MVP бота

Источник требований: [ТЗ](../product/mvp.md).

## Этапы

1. **Основа и хранение.** Схема пользователей, игр, участников, назначений и состояния диалога; миграция; запуск локального PostgreSQL.
2. **До жеребьёвки.** Регистрация через `/start`, главное меню, создание игры, приглашение, вступление, список игроков и пожелания.
3. **Жеребьёвка.** Проверки прав и числа игроков, атомарное сохранение назначений, приватная рассылка и просмотр своего получателя.
4. **Управление.** Мои игры, выход и удаление участника до жеребьёвки, настройки, удаление игры с подтверждением.
5. **Проверка.** Интеграционный сценарий A/B/C, запрет повторной жеребьёвки и доступа к чужому назначению, typecheck, тесты, lint, миграция.

## Критерий готовности

Сценарий из раздела 26 ТЗ проходит на изолированной базе. Все действия из пунктов MVP доступны через кнопки в личном чате.

## Результат и проверка

Все пять этапов реализованы. Полный сценарий A/B/C и отрицательные проверки прав и состояния проходят в `tests/bot.test.ts` на PostgreSQL. Проверены `npm run migrate`, `npx tsc --noEmit`, `npm test`, `npm run lint` и сборка Docker-образа.

Реальное получение сообщений в Telegram не проверялось: для этого нужен действующий токен и пользователи, открывшие чат с ботом. Отправка результатов имеет семантику «не менее одного раза»: при сбое между отправкой и записью статуса сообщение может повториться.
