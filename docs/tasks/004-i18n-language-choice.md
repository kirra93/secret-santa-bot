# Два языка интерфейса и выбор пользователя

Источники: [ТЗ MVP](../product/mvp.md) и [текущая архитектура](../architecture/overview.md).

## Работа

1. Вынести тексты, кнопки и сообщения об ошибках в типизированный каталог русского и английского языков.
2. Переводить экраны, пошаговые диалоги, приглашения, встроенные варианты бюджета и личные уведомления о результате жеребьёвки; пользовательский текст бюджета оставлять без изменений.
3. Добавить кнопку выбора языка в главное меню и хранить явный выбор в `users.locale` (`ru` или `en`). Если значение `null`, использовать русский. Язык Telegram не должен перезаписывать выбор пользователя.
4. Обновить README на английском и описать поведение языка в документации.
5. Проверить переключение языка, сохранение настройки после `/start` и язык уведомлений интеграционным тестом.

## Результат и проверка

Работа завершена. Каталог переводов находится в `src/i18n.ts`. Выбор языка доступен из главного меню; сохранённое значение применяется во всех обработчиках, scenes и отложенной рассылке. Миграция `0003_silky_stingray.sql` добавила поле, а `0004_lush_maestro.sql` сделала его nullable и сбросила прежние автоматически определённые значения в `null`: до появления кнопки ни один пользователь не выбирал язык явно.

Миграции применены на изолированной тестовой базе. Прошли `npx tsc --noEmit`, `npm test` и `npm run lint`. Интеграционный тест проверяет русский по умолчанию даже при английском языке Telegram, переключение в обе стороны, сохранение выбора, английские приглашение и уведомление о жеребьёвке. Реальная доставка через Telegram не проверялась.
